# LeetCode API research and limitations

Research: Zed Tasks documentation, [LeetCode terms](https://leetcode.com/terms/), and the [LeetCode-OpenSource VS Code extension](https://github.com/LeetCode-OpenSource/vscode-leetcode), in particular `src/shared.ts`, `src/leetCodeExecutor.ts` and `src/commands/submit.ts`. The extension delegates submission to `vsc-leetcode-cli`, not a self-contained GraphQL implementation. No extension source code has been copied.

- The extension identifies `https://leetcode.com/graphql` and `https://leetcode.cn/graphql` (CN's user GraphQL uses a trailing slash). These are website endpoints, not a documented stable public developer API.
- Community clients describe `problemsetQuestionList` for filtered lists and `questionData` for details, including Python3 code snippets, metadata and example data. Fields and behavior can change; CN and global may differ in schema, localized content, authorization and available features. We did not verify the current live schema or service behavior.
- The extension delegates to `vsc-leetcode-cli`. In the [underlying open-source CLI](https://github.com/LeetCode-OpenSource/leetcode-cli), `lib/plugins/leetcode.cn.js` configures `/problems/$slug/submit/` and `/submissions/detail/$id/check/`; `lib/plugins/leetcode.js` builds a POST containing `lang`, internal `question_id`, `typed_code`, `test_mode` and `judge_type`, then polls the submission ID until `state` is `SUCCESS`. Its older detail query uses `codeDefinition`, `sampleTestCase`, `metaData`, and `translatedContent`. These are historical implementation evidence, not confirmation of today's schema, access rights, payload or polling behavior. No code was copied.
- The international terms explicitly prohibit crawling and scraping. The [China terms](https://leetcode.cn/document/terms/) differ: section 3.1.6 restricts unauthorized access or use including copying and vertical search; 3.1.7 concerns unauthorized tools that interfere with the service; 3.3 concerns separation of the service from authorized platforms; 10.3.2 concerns using automated tools to obtain platform entitlements. These do not establish a blanket ban on every single interactive request, nor do they establish that this independent CLI is authorized. We have not obtained permission or verified the extension's authorization for the China service. The user has stated that their use is allowed. Limited user-triggered China-site requests, including experimental submission, are implemented; users are responsible for ensuring applicable authorization and terms. This is not a legal conclusion.

## Browser login investigation

The VS Code extension's `src/shared.ts` uses `https://leetcode.cn/authorize-login/vscode/?path=leetcode.vscode-leetcode`. Its `leetCodeManager.ts` receives a `cookie` query parameter through VS Code's URI handler. An unauthenticated request to the authorization page redirected to the site's login page, but no authenticated callback was tested. The extension's `vscode://` callback does not demonstrate that arbitrary localhost callbacks or an OAuth device flow are supported. No official China-site CLI callback or device-flow documentation was found. This tool does not register or intercept the VS Code URI scheme. It instead offers an opt-in isolated Chrome login and reads only that newly created browser context's China-site cookies, with explicit user consent. It does not access existing browser profiles. Never share callback URLs containing cookies.

## Adapter

`client.py` is the replaceable boundary. China detail and list queries have been probed; online reads are limited to explicit commands and do not use credentials. The submission adapter uses the historical endpoint shape, environment-provided `LEETCODE_SESSION` and `LEETCODE_CSRF_TOKEN`, explicit invocation, timeouts and bounded polling. It does not read existing browser profiles, write credentials to the workspace, follow redirects for authenticated requests, or bypass access controls. `lc login` stores verified credentials in macOS Keychain after an isolated browser login. Login and submission have also been verified once with a real China-site account: a Two Sum submission returned Accepted. This is not a guarantee of future endpoint stability.

Use `lc fetch <slug>` for a China-site problem or `lc fetch --import-file FILE` with a manually authored JSON file. Submission uses `lc submit`; premium content and permissions remain subject to the site's rules.
